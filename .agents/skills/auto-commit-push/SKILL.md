# Автоматический Commit & Push

Этот скилл является **ОБЯЗАТЕЛЬНЫМ** для всех задач, связанных с изменением кода или файлов в репозитории. 

## Правило

После каждого завершенного **логического шага** (например, реализации функции, рефакторинга файла, добавления тестов или исправления бага) вы **ОБЯЗАНЫ** зафиксировать изменения в Git и отправить их в удаленный репозиторий.

## Инструкция по выполнению

1. **Добавление файлов:**
   Выполните команду для добавления измененных файлов:
   `git add .` (или укажите конкретные файлы, если это необходимо).

2. **Коммит:**
   Сделайте коммит с понятным и кратким описанием того, что было сделано на этом логическом шаге. Желательно придерживаться формата Conventional Commits, если это применимо (например, `feat: ...`, `fix: ...`, `docs: ...`).
   `git commit -m "feat: added new user validation logic"`

3. **Отправка изменений:**
   Отправьте изменения в текущую ветку (push).
   `git push origin HEAD`

## Решение проблем

- Если `git push` отклонен (rejected) из-за конфликтов или необходимости выполнить `pull`:
  - Выполните `git pull --rebase origin HEAD` (или аналогичную команду для слияния изменений).
  - Убедитесь, что нет конфликтов, и повторите `git push origin HEAD`.

**Не ждите завершения всей задачи, чтобы сделать один большой коммит.** Дробление на логические шаги позволяет легче отслеживать историю изменений и откатывать ошибки.
